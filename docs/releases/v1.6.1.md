# TypeScript WSDL Client v1.6.1

## Accurate native assessment and safe syntax refusals

Native assessment recognizes empty extensions of `xs:anyType` without mistaking inherited content for an invalid extension. Unknown WSDL and SOAP names produce typed refusals instead of unexpected exceptions. See the root [README](../../README.md).

## What This Improves

Schema assessment reports the native result accurately for extensions with absent content or an empty sequence. Explicit `anyType` references still lack qualified component correspondence, so these schemas remain ineligible for checked generation and runtime admission.

## Highlights

- Empty extensions reuse authentic builtin particle identity while preserving source declarations and strict extension rules.
- Ambiguous local element additions remain rejected by the existing attribution checks.
- SOAP 1.2 action metadata and bounded shared-group preparation retain focused TypeScript regression coverage.
- Qualification workflows use current artifact uploads with the existing zipped artifact contract.
- Existing XML parser and lint dependencies are refreshed; no dependency packages or toolchains are added.

## Upgrade Notes

No configuration or artifact migration is required. Existing generated clients and gateways retain their contracts. Consumers inspecting native assessment may now see `schema: "established"` for the two empty-extension forms; correspondence remains inconclusive and generation remains refused.

## Validation

- Product conformance and installed consumer checks preserve existing generation and runtime behavior.
- Release preflight validates package contents, generated examples and standalone agent skill artifacts.
