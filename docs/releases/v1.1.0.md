# TypeScript WSDL Client v1.1.0

## Generated TypeScript with explicit lint ownership

This minor release adds automatic ESLint suppression preambles to newly emitted TypeScript and documents path exclusions for consumers with restrictive lint policies.

## What This Improves

Regenerated client and gateway files carry their ESLint directive automatically, eliminating repeated manual edits. App and generated-test scaffolds use distinct wording that explains when to remove suppression as those files become maintained source.

Preambles are packaged resources selected by logical artifact scope and applied at the final file-write boundary. Resource validation and installed-package consumer tests ensure the behavior works outside the repository checkout, including conditional helpers and programmatic generation.

## Highlights

- Add one preamble to every complete generated TypeScript file, including streaming helpers and stub routes.
- Preserve existing app/test files unless their existing force option requests regeneration.
- Propagate TypeScript generation failures instead of logging write failures as successful generation.
- Document consumer global ignores, strict inline policies, parser limitations, and hook behavior.
- Verify real ESLint suppression alongside maintained-source controls and installed-package tests.

## Upgrade Notes

CLI syntax, public API signatures, catalog semantics, and runtime behavior are unchanged. Regeneration adds a comment preamble to TypeScript output; existing editable scaffolds retain their current contents unless explicitly regenerated.

`/* eslint-disable */` suppresses rule reports only when inline configuration is allowed. It does not bypass parsing or TypeScript checking, and clean files may produce unused-disable diagnostics. Use the [consumer ESLint guidance](../generated-code.md#generated-preambles-and-eslint) to exclude generated paths while keeping maintained-source policies intact.

Remove the suppression when adopting an app or test scaffold as maintained source, and keep adopted files outside ignored generated directories. No runtime or schema migration is required.
