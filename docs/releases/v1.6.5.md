# TypeScript WSDL Client v1.6.5

## Deterministic decoding for checked SOAP responses

Checked component clients and gateways now accept strict ASCII and explicitly labelled UTF-16LE/BE responses without a byte order mark.

## What This Improves

SOAP services using these response encodings can return validated values through the existing checked SOAP 1.1/1.2 adapter and generated gateways. Decoding preserves exact characters and original response bytes while retaining native schema, scalar, mapping and fault validation.

## Highlights

- Accept case-insensitive `US-ASCII` and `ASCII` labels with strict seven-bit byte validation.
- Decode BOM-less UTF-16LE/BE selected by HTTP charset, XML declaration, or agreeing assertions from both.
- Preserve UTF-8, exact ISO-8859-1 and matching BOM-marked UTF-16 compatibility.
- Exercise encoded success, declared/protocol faults and nonempty one-way refusal in installed consumers.
- Document the checked response profile and remaining encoding, envelope and metadata work.

## Upgrade Notes

Update the package used by the checked runtime; no generated artifact format or runtime binding changes are required for this response-decoding extension. Metadata/source decoding, outgoing UTF-8, frozen direct clients and legacy defaults retain their existing contracts.

All present HTTP charset, XML declaration and BOM assertions must still agree. Generic `UTF-16` requires a BOM; matching explicit LE/BE labels with a BOM remain accepted for compatibility. Unknown charsets, high ASCII bytes, malformed code units and illegal or truncated XML refuse rather than producing replacement characters or partial success.

## Validation

Release qualification covers independent byte/code-point expectations, owned HTTP and verified HTTPS exchanges, offline inspection and installed generated clients/gateways. Local conformance, release preflight, package contents and agent skill artifacts are verified alongside Linux/Windows Node 24/26 qualification.

## Notes

This release completes the selected checked response-byte batch. Envelope attributes/roles, metadata charset authority and broader charset support remain separate work. No production SOAP provider is contacted. Publication remains a maintainer action after draft and artifact verification.
