# TypeScript WSDL Client v1.1.6

## Opt-in checked gateways from WSDL files and URLs

This patch makes the checked WSDL-to-gateway workflow available for early testing and feedback. It adds structured component generation, automatic dependency acquisition and simpler endpoint setup without changing the existing generation defaults.

## What This Improves

Choose `pipeline --model checked-components-v1` to generate a typed client, OpenAPI, Fastify gateway, runnable app and scaffold tests from a supported WSDL file or URL. Unambiguous services need no authored selectors or resource maps. Declared same-origin dependencies are acquired recursively; one reusable project decision permits an additional metadata origin, while explicit offline and restrictive controls remain effective.

The selected WSDL endpoint or a configured override supplies routing intent when an operation is invoked. Optional restrictions still narrow permitted destinations, including empty deny-all. Copied source snapshots support offline metadata use at runtime, and planning reports explain blockers or draft a missing-schema location for recovery.

Start with [Try Opt-in Checked Generation](../checked-generation.md) for a bundled installed trial, configuration, scope and feedback instructions. The [checked gateway reference](../checked-gateway.md) covers advanced configuration and the separate narrow direct preview. This is a qualified buffered SOAP 1.1 slice, not universal WSDL/XSD support, automatic companion discovery, checked streaming or production-provider acceptance.

## Highlights

- Generate checked clients and gateways for qualified imported, nested, repeated, inherited and attributed records.
- Inspect WSDL-first planning reports and supply missing schema locations through editable recovery drafts.
- Acquire declared URL dependencies and retain original source provenance for offline runtime checks.
- Derive component endpoint intent while preserving explicit destination restrictions and TLS verification.
- Preserve explicit typed companion payload behavior, checked faults and legacy JSON/raw/streaming contracts.
- Correct legacy boolean-attribute and simple-content conversion and reject asynchronous response conversion failures.
- Compile structured component fault schemas without recursive reference resolution during gateway startup.
- Add a testing guide, feedback path and packaged agent references for the opt-in workflow.
- Patch redirect header handling and development glob dependencies with consumer compatibility tests.

## Upgrade Notes

Install `@techspokes/typescript-wsdl-client@1.1.6` on Node.js 24 or newer. Omitting `--model` preserves legacy generation; checked generation remains an explicit choice. The narrower `checked-direct-v1` mode retains its own source, selection and loopback endpoint requirements.

Regenerate experimental checked clients, contracts, sources, gateways and server scaffolds together with the matching runtime. Component runtime compatibility changed, so do not mix older experimental outputs with new artifacts. Existing consumer-owned server/config/test files are preserved unless their force option is deliberately selected; review customizations before refreshing them.

Refresh consumer lockfiles separately to obtain transitive security patches. Missing required declarations and strict wildcard failures remain refusals; the release adds no validation bypass or XML response negotiation.
