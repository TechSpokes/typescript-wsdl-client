# TypeScript WSDL Client v1.8.0

## Exact values for checked SOAP unions and lists

Checked clients and gateways can handle XML Schema fields that admit several atomic value types, including lists of those values. Lexical spellings such as `"+01.00"` survive the trip between SOAP and HTTP JSON.

## What This Improves

Checked generation supports qualified atomic unions in SOAP 1.1 and 1.2 document/literal services. The native validator selects the first matching declared member. Generated clients and HTTP gateways carry each ordinary union value as a string and each ordinary union list as an ordered array of string tokens, preserving leading zeros, signs and decimal precision.

## Highlights

- Accept qualified atomic string, decimal, integer and boolean union members.
- Represent ordinary lists as ordered string arrays such as `["+01.00", "true", "AUTO"]` when the schema admits those tokens.
- Keep the whole list as a string when its pattern requires a lexical witness.
- Compare fixed values using native typed equality and apply defaults with their original schema spelling.
- Carry these values through requests, responses, declared faults and qualified literal headers.

## Upgrade Notes

Update the generator and runtime together and regenerate matching checked artifacts when adopting the new value types. Pass each ordinary list item as a single nonempty string token without XML whitespace. Generated OpenAPI describes the value shapes, and native validation checks membership and source constraints.

The capability is available through `checked-components-v1`. RPC lists, unions that contain lists and wider or contextual member families remain outside the supported subset. See the [migration guide](../migration.md#from-170-to-180) and the [checked gateway value contract](../checked-gateway.md#native-facets-lists-and-lexical-atomic-unions).

## Validation

The reviewed union and union-list implementations passed independent source and value checks, owned SOAP request, response and fault exchanges, and installed package qualification on Linux and Windows with Node.js 24 and 26. The combined implementation passed standalone conformance and product CI.
