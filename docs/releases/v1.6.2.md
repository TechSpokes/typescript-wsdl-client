# TypeScript WSDL Client v1.6.2

## Selected upstream HTTP metadata

Checked SOAP clients can observe explicitly selected upstream HTTP response headers alongside native validated results and response refusals. Generated gateways can separately opt into publishing this metadata through fixed informational header names.

## What This Improves

Consumers can read upstream rate limits and actual HTTP status without bypassing native SOAP validation or modifying application values. Complete HTTP 429 observations remain available even when the non-SOAP body is refused; rate scheduling, backoff and retries stay in consumer code.

## Highlights

- Observe selected headers with `soap.httpResponseHeaders`, or use `[]` for status only.
- Retain immutable request-owned metadata across complete-response failures, SOAP faults and application errors.
- Opt into gateway publication with `httpResponseHeaders` in existing checked configuration.
- Preserve REST bodies and statuses while documenting optional informational headers in OpenAPI.
- Bound metadata copies and exclude every unselected header from the observation.

## Upgrade Notes

Existing defaults remain unchanged. Regenerate matched checked clients and gateways to adopt the new option; current V1-V5 runtime handshakes, capsule versions and source fingerprints are unchanged. Frozen direct-preview and legacy clients keep their existing behavior.

Client observation alone does not publish downstream headers. Gateway routes pin their own generation-time selection and publish `x-wsdl-tsc-upstream-status` plus `x-wsdl-tsc-upstream-header-<normalized-name>`, with multiple values joined by comma and space. An upstream 429 normally still returns downstream 502.

See [selected upstream HTTP response headers](../checked-gateway.md#selected-upstream-http-response-headers) for exact bounds, failure availability and configuration.
