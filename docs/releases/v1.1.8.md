# TypeScript WSDL Client v1.1.8

## Checked generation with richer values and clearer setup

This patch brings the complete opt-in checked component workflow to users upgrading from published v1.1.5. It carries forward the unpublished v1.1.6/v1.1.7 preview and adds explicit nil, keyed mixed/open values, native scalar constraints, application groups and clearer diagnostics while preserving legacy defaults.

## What This Improves

Choose `pipeline --model checked-components-v1` to generate a typed SOAP client, OpenAPI, Fastify gateway, runnable app and scaffold tests for supported document/literal SOAP 1.1 contracts. Unambiguous sources select their service and operations automatically. Local files and permitted WSDL URLs use recursive declared imports/includes; additional metadata origins require an explicit project permission. Missing locations and ambiguous selections produce actionable planning reports and editable resolution drafts.

Generated hosts load their copied source bookkeeping without an authored runtime configuration file. Calls use the selected WSDL address or an explicit override; optional endpoint restrictions remain restrictive, including empty denial lists. Runtime metadata stays offline, with physical-source, digest and native artifact compatibility checks retained independently of startup health.

Checked values now preserve nil attributes, mixed text/child order, namespace identity and source-permitted open content through client, HTTP, response and declared-fault paths. Native facets, restricted lists and primitive-string unions retain their checks beyond what OpenAPI can express. Optional source-derived application groups give reconstructible choices and repeated sequences named application shapes without changing existing output when the option is absent.

Start with [Try Opt-in Checked Generation](../checked-generation.md), the [checked gateway reference](../checked-gateway.md) and the [mapping contract](../mapping-contract.md). The bundled trial is synthetic; its scaffold tests do not invoke a business SOAP operation.

- Refresh dependency minimums and verify current generated-app pins while retaining the Node.js 24 floor.
- Ship consumer guides and generation resources without research archives, unresolved maps or unused runtime copies.
- Separate consumer testing guidance from maintainer checks and retain independent product reference evidence.

## Upgrade Notes

Use Node.js 24 or newer. Omitting `--model` preserves legacy generation. Existing published v1.1.5-issued direct clients retain `checkedDirectRuntimeV1`, its protocol and owned-loopback restrictions. The unpublished `checked-direct-v1` generation choice and `checkedDirect` pipeline option were removed; migrate those experiments to `checked-components-v1` and regenerate the complete project.

Regenerate matched checked clients, contracts, capsules, copied sources and gateways with the installed runtime. Component execution uses `checked-component-runtime-v2`; generated bookkeeping uses the separate `checked-source-resources-v2` format. Review consumer-owned server/config/test customizations before deliberately refreshing scaffolds with their existing force options. Complete older explicit source configurations remain supported as advanced inputs; incomplete configurations refuse and explicit empty restrictions retain denial semantics.

Nil uses an explicit object, not `null`. Newly supported mixed/open mappings use their source-selected keyed grammar; already accepted component scalar/record/array/ordered values and shipped direct/legacy contracts retain their shapes. Application groups require explicit opt-in; copy naming targets from a fresh inventory after relevant source changes. Refresh consumer lockfiles separately for transitive security fixes.

Explicit companion associations retain `records-with-declared-wrapper-scope`: the complete companion payload is buffered, required schema metadata remains mandatory and ambiguous record paths require a choice. They do not discover companions automatically or prove full-response validity in a merged declaration universe. The narrow `checked-assessment-v1` API remains diagnostic; use component planning for component readiness.
