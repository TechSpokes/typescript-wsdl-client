# TypeScript WSDL Client v1.4.1

## Composable checked OpenAPI documentation

Checked generation emits documentation suitable for the public `composeOpenApiDocuments` API while retaining each service's structural JSON shapes.

## What This Improves

Developers can regenerate independent checked service specifications and compose their documentation without a downstream schema transformation. Definition references retain their original operation and role ownership, including declared faults; configured grouped names remain stable.

## Highlights

- Checked documentation relocates local definitions into deterministic OpenAPI components.
- Request, response and declared fault references retain their independent schema scopes.
- Runtime schemas, capsules and native supplemental validation retain their existing contracts.

## Upgrade Notes

Regenerate checked specifications with this version to adopt composable documentation. Existing runtime artifacts remain usable. Archived 1.4.0 specifications containing embedded resources remain refused by the composer. Structural JSON documentation does not replace native XML validation.

See the [migration guide](../migration.md#from-140-to-141) and [checked gateway guide](../checked-gateway.md).

## Validation

Validation covers structural acceptance before and after composition, generated checked gateways against owned SOAP servers, unchanged runtime schemas and capsules, package contents, and the standalone agent skill artifact. Native XML validation remains supplemental to the documented JSON structures.
