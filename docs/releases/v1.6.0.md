# TypeScript WSDL Client v1.6.0

## Independently validated application-error responses

Scoped companion operations can opt into separately pinned application-error grammars. Matching clients and gateways distinguish successful records, validated application errors and SOAP Faults while preserving complete error wrappers and attributes. See the root [README](../../README.md).

## What This Improves

An upstream error with a different declared structure can become a typed non-success result without weakening the success grammar. Exact QName paths select one independently validated full response; unknown, ambiguous or malformed branches refuse without trying another grammar.

## Highlights

- Explicit versioned branch sets pin every original resource in each independent error grammar.
- Application errors retain their configured branch identity and complete native value at HTTP 502.
- Matching TypeScript and OpenAPI distinguish success, application errors and SOAP Faults.
- Portable capsules require explicit physical source authority and fresh offline qualification for every branch.

## Upgrade Notes

Existing single-success projections and runtime bindings keep their contracts. Opt in through `responseBranches` alongside an existing success `recordProjections` association, then regenerate clients, capsules, source inventory, gateways and OpenAPI together. Branch-enabled SOAP 1.1 and 1.2 use V4 and V5 bindings respectively; older bindings refuse the new artifacts.

Handle `application-error` with its `branch` and full `value`. Branch-enabled SOAP Fault HTTP envelopes also include `kind: 'soap-fault'`. Mixed-version service clients require the matching runtime per operation. See the [migration guide](../migration.md#from-15x-to-160) and [branch configuration](../checked-gateway.md#independently-validated-application-error-branches).

Delivery remains buffered under shared caller capacity and cancellation controls. The first family requires distinct immediate discriminator QNames and mandatory exact descendant paths; it excludes streaming, namespace stripping, permissive wildcards, vendor codes and per-record selection.

## Validation

- Native and public API regressions cover exact selection, independent grammars, source pins and strict refusals.
- Installed generated SOAP 1.1 and 1.2 consumers qualify independently expected XML and HTTP outcomes.
- Relocation, stale sources, runtime compatibility, capacity and cancellation cleanup are qualified offline.
- Product conformance, release preflight, package contents and standalone skill artifacts validate the candidate.
