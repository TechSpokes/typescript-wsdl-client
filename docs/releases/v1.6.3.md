# TypeScript WSDL Client v1.6.3

## One-way SOAP acknowledgements and exact HTTP metadata names

Checked generation supports WSDL 1.1 input-only document/literal operations over SOAP 1.1 and SOAP 1.2. Generated gateways acknowledge complete allowed empty exchanges with HTTP 202 and no response body, and can explicitly name selected upstream HTTP metadata headers.

## What This Improves

Input-only operations can use the existing native source validation, request codec, verified transport and gateway pipeline without inventing application response values. Consumers can separately select and name informational HTTP fields while native SOAP validation, private-header exclusion and existing request-response defaults remain intact.

## Highlights

- Match source-selected SOAP versions and input names through additive V6/V7 one-way bindings.
- Distinguish transport acknowledgement from application response, protocol fault and explicit refusal.
- Return an empty gateway 202 without JSON Content-Type, a body schema or a polling contract.
- Configure full selected header destinations and a status destination, retaining unmapped namespaced defaults.
- Refuse unsafe, colliding, malformed or unselected naming configuration before artifact writes or dispatch.
- Lead the README with product use and consolidate compatibility guidance in the existing migration guide.

The [one-way contract](https://github.com/TechSpokes/typescript-wsdl-client/blob/v1.6.3/docs/checked-gateway.md#one-way-operations) defines empty 200/202/204 interoperability allowances, nonempty-body refusals and native protocol-fault handling. [HTTP metadata configuration](https://github.com/TechSpokes/typescript-wsdl-client/blob/v1.6.3/docs/checked-gateway.md#selected-upstream-http-response-headers) defines exact lowercase identities, serialization, finite safety exclusions and unchanged bounds.

## Upgrade Notes

Regenerate matched one-way clients, capsules, source inventories, gateways and OpenAPI together to adopt `checkedComponentRuntimeV6` for SOAP 1.1 or `checkedComponentRuntimeV7` for SOAP 1.2. Existing V1-V5 request-response bindings, direct preview and legacy defaults remain unchanged and refuse one-way artifacts before I/O. Mixed services use each operation's matching binding.

Handle `soap-acknowledgement` without reading `value`, `decoded`, `fault` or `branch`. Its actual upstream status and owned empty bytes establish complete transport acceptance only. They do not prove business processing and must not trigger automatic retries of uncertain operations.

`httpResponseHeaderNames` and `httpResponseStatusHeaderName` require an explicit `httpResponseHeaders` selection, including `[]` for status only. Omitted names preserve the current fixed namespace. Client observation retains normalized upstream identities independently of aliases, and observation alone never publishes gateway headers.

Preserve consumer-owned app/config/test scaffolds under the existing skip/force rules and run consumer checks. The [migration guide](https://github.com/TechSpokes/typescript-wsdl-client/blob/v1.6.3/docs/migration.md#from-16x-to-163) retains current and older regeneration warnings.

## Validation

- Owned HTTP and verified HTTPS assertions cover both SOAP versions and finite acknowledgement/error outcomes.
- Compatibility and source/configuration refusals cover retained bindings and selector-scoped output configuration.
- Relocated production-only installed consumers exercise generated apps and native wire execution without checkout fallback.
- Standalone conformance and final release preflight qualify the complete candidate sequentially.
- Preflight owns product CI, reference/installed/smoke checks, npm package validation and agent skill packaging.

## Notes

No production SOAP provider is called by this delivery. RPC/multipart one-way messages, nonempty acknowledgement envelopes, retries, checked streaming and broader authentication/header capabilities remain outside this release. The finite destination policy does not claim to enumerate future browser controls. Publication of this draft and the npm package remains a maintainer action.
