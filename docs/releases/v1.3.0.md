# TypeScript WSDL Client v1.3.0

## Checked SOAP 1.2 with binding isolation

Version 1.3.0 adds opt-in checked SOAP 1.2 document/literal execution through the existing native compiler, XML codec and buffered SOAP adapter. Legacy generation remains the default. See the root [README](../../README.md).

## What This Improves

Generated clients and gateways use the selected SOAP binding for envelope, action and content type. Mixed SOAP 1.1/1.2 ports keep independent actions during concurrent calls, and incompatible source artifacts or envelopes refuse rather than crossing bindings.

SOAP 1.2 faults retain expanded code/subcodes, language-tagged reasons and optional Node/Role metadata. Declared detail uses the existing native mappings. Valid protocol faults without declared detail retain raw response bytes without inventing typed application values.

## Highlights

- SOAP 1.2 document/literal requests, responses and faults use the existing transport and codec.
- SOAP 1.2 header processing respects receiver roles and mandatory blocks without granting security capabilities.
- Versioned source artifacts preserve selected service, port, binding and action requirements.
- The additive runtime binding preserves existing SOAP 1.1 and shipped direct-client contracts.

## Upgrade Notes

Existing SOAP 1.1 clients retain their runtime handshake. To adopt SOAP 1.2, regenerate matched client, capsule, OpenAPI and gateway artifacts with 1.3.0. SOAP 1.2 clients use `checkedComponentRuntimeV2` and `checked-component-soap12-runtime-v1`. The [migration guide](../migration.md#from-12x-to-130) describes fault narrowing and consumer-owned scaffold preservation.

Live Escapia SOAP 1.2 acceptance is not established. Protocol qualification uses synthetic owned services and isolated installed consumers. Streaming, SOAP 1.2 RPC/encoded, broader authentication, application headers and attachments remain separate capabilities.
