# TypeScript WSDL Client v1.12.1

## Closed operation qualification and checked apps

Checked generation can qualify a selected closed document/literal operation from a broader pinned schema graph. Checked apps also support literal `#` and `%` in client and gateway directory names, and checked planning explains missing WSDL ports and native schema refusals.

## What This Improves

Integrators can select a closed operation using the original source snapshots. Checked proves the selected dependencies and repeats the proof at runtime. A generated app can also start with the artifact layout you selected, and scaffold tests run through the usual test command before a build.

## Highlights

- Set `"qualificationScope": "closed-operation-v1"` in checked configuration to qualify a closed document/literal request-response operation. The plan still reports whole-source legality.
- Keep literal client and gateway paths through generation, strict build, runtime loading, and regeneration.
- See native schema rule and declaration details in checked planning diagnostics when available.

## Upgrade Notes

Checked generation defaults to whole-source qualification. Regenerate the matched artifacts when opting into [closed operation qualification](../checked-gateway.md#closed-operation-qualification).

If your checked app uses an affected path, regenerate the matching artifacts and refresh its host and tests. For customized scaffolds, apply the loader changes from freshly generated files and retain your edits. See [checked generation](../checked-generation.md#generate-the-checked-stack-in-separate-commands).

## Validation

- Installed Forecast covers ordinary and literal-delimiter directory layouts, scaffold tests before build, relocated SOAP/HTTP exchange, and regeneration.
- The original NOAA WSDL covers owned SOAP 1.1 RPC/encoded exchange with an opaque string output.
- ONVIF `GetDeviceInformation` completes an owned SOAP 1.2 exchange after relocation using all 11 original pins and closed operation qualification. Default checked mode exercises whole-source refusal before SOAP dispatch.
- Scoped validation covers missing and stale snapshots, a denied endpoint, invalid input and a SOAP response missing a required field.
