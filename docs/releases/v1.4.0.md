# TypeScript WSDL Client v1.4.0

## Explicit contract corrections and truthful SOAP diagnostics

Version 1.4.0 adds consumer-owned JSON source corrections, offline SOAP response inspection, and checked SOAP 1.1 protocol faults without fabricated application values. Legacy generation remains the default. See the root [README](../../README.md).

## What This Improves

Developers can maintain small, digest-pinned JSON corrections instead of editing large vendor metadata files. Effective snapshots pass through the ordinary compiler, TypeScript generation, OpenAPI, gateway validation and source capsules together; deployed gateways do not need correction recipes or upstream metadata access.

Offline inspection assesses saved response bytes without credentials or SOAP dispatch. It preserves separate wrapper and companion outcomes and selects an operation from the complete checked configuration without dropping correction pins for other companion sources. Draft corrections leave semantic choices to the consumer.

New checked SOAP 1.1 clients distinguish valid protocol faults from typed declared fault values. Declared detail still requires native validation, and malformed protocol structures remain refused. Existing runtime bindings keep their previous contracts.

## Highlights

- JSON corrections set particle occurrences, narrow wildcard namespaces, and insert explicitly typed sequence elements.
- Optional standard wrapper metadata follows source-declared occurrence constraints.
- Offline reports distinguish XML-only assessment from supplied HTTP response metadata.
- Multi-operation inspection preserves the complete project source authority before selecting one operation.
- Checked SOAP 1.1 protocol faults retain metadata and response bytes without claiming a decoded application value.

## Upgrade Notes

Existing clients and source capsules remain usable through their original runtime bindings. Regenerate matched SOAP 1.1 client, OpenAPI and gateway artifacts to adopt `checkedComponentRuntimeV3` with `checked-component-soap11-runtime-v1`; SOAP 1.2 retains V2. Narrow protocol fault results before accessing typed application values.

Use `sourceCorrectionsFile` only with explicit consumer-owned source pins and correction choices. A source change requires reviewing pins and regenerating the complete project. Arbitrary schema replacement, inferred provider types and runtime XML rewriting are outside the correction language; existing replacement snapshots remain available.

See the [migration guide](../migration.md#from-13x-to-140), [checked gateway guide](../checked-gateway.md), and [API reference](../api-reference.md).

## Validation

Generic owned fixtures cover strict declared values, protocol fault boundaries, multiple scoped operations, source freshness, offline reconstruction and generated consumers. Local release preflight owns the final full product CI, package validation, smoke checks and agent skill packaging. Hosted checks and a release PR are intentionally deferred until the maintainer requests that step.

Private read-only provider calls supplement the generic regressions; their payloads and credentials are not package contents. Provider authorization, invalid payload scalars and alternate undocumented error wrappers remain separate from protocol-fault support. Checked responses remain buffered; this release does not add checked streaming.
