# TypeScript WSDL Client v1.5.0

## Scoped diagnostics and deliberate type corrections

Checked payload failures identify their source universe, declaration, datatype and known-field location without exposing response values or source locators. Trusted local inspection supplies original pinned targets for explicitly reviewed element and attribute type corrections.

## What This Improves

Consumers can locate a rejected XML field and author a small guarded source change without replacing an entire schema snapshot. Existing source pins, native validation and matched generated artifacts keep the effective contract explicit and reproducible.

## Highlights

- Optional bounded diagnostics retain scoped source identity and redact unknown payload names and values.
- Trusted authoring recovers original targets after prior corrections or reports an explicit unavailable reason.
- `set-declared-type` guards authored element and attribute references with original digests and expected expanded types.
- Existing named types and legal XML Schema builtins resolve within the declaring source universe and import authority.

## Upgrade Notes

Existing runtime bindings and failure kinds remain supported. Regenerate matched clients, capsules, gateways and OpenAPI to adopt generated diagnostic metadata; consumers should accept additive optional fields in the existing inspection/report contracts. Request `includeCorrectionTargets` only in trusted local workflows because its original selectors contain source locators.

Changed effective source bytes require fresh qualification and regeneration. A shared declaration changes every use within its configured project; stale pins, unsupported inline/ref forms, missing imports and illegal replacements refuse. Preserve original sources and never refresh pins or weaken types from observed response values automatically.

Changing URI to string admits embed content and removes the URI guarantee. Changing dateTime to string also admits nonsense; an existing constrained string can check layout without proving calendar validity or normalizing timezones. See the [migration guide](../migration.md#from-14x-to-150) and [source-correction guide](../checked-gateway.md#consumer-owned-source-corrections).

## Validation

- Native regressions cover scoped provenance, strict refusals, guarded replacements and unchanged source bytes.
- Installed generated consumers qualify public authoring, offline relocation and independently expected SOAP/HTTP outcomes.
- Product conformance, research checks and full release preflight validate the candidate before tagging.
- Package contents and the standalone agent skill ZIP and checksum manifest are validated for draft delivery.
