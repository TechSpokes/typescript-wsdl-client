# TypeScript WSDL Client v1.2.0

## Independent services, mapped streams and bounded RPC

This candidate combines scoped legacy compilation, native multi-service legacy gateways, stream DTO and transport corrections, and the bounded checked SOAP 1.1 RPC/encoded profile. Publication remains a maintainer action. See the root [README](../../README.md).

## What This Improves

Independent sources can share a discoverable REST API while retaining separate clients, catalogs, endpoints and security. Scoped types survive name collisions, and incremental records use generated DTO mapping. The bounded checked RPC profile executes opaque string exchanges without claiming geographic correctness.

## Highlights

### Multi-service gateways and scoped declarations

Use `pipeline --services-config` or `runMultiServicePipeline` to generate independent WSDL clients and service routers behind one typed aggregate gateway and one OpenAPI definition. Service-qualified component references and operation identifiers preserve ownership when services reuse names. Runtime client construction keeps each WSDL, endpoint, credentials and transport settings explicit.

The legacy compiler preserves local declaration identities instead of merging declarations whose generated display names collide. Non-colliding names retain their existing behavior. See the [gateway guide](../gateway-guide.md#multi-service-setup) and [API reference](../api-reference.md#runmultiservicepipeline).

### Incremental legacy responses

Configured NDJSON and JSON-array responses map complete XML records through the existing DTO conversion before delivery. Attribute fields, scalar policies, simple content, XML lists and repeated fields follow generated metadata. Requests reuse node-soap's schema serializer for namespace qualification, and stream calls honor supported endpoint, security, certificate, deadline and cancellation settings.

The Escapia Main and Content proof exposes 17 routes through one gateway and API definition. Six Test-target reads passed, including company and content reads for ABC Rentals (`7007`) and A Perfect Vacation Rental (`1273`); all 21 streamed records validated against the advertised schemas. Vendor requests explicitly disabled array-wrapper flattening. This qualifies those selected reads, not every operation or production.

### Checked RPC/encoded profile

Checked component generation supports the bounded NOAA-style SOAP 1.1 RPC/encoded contract: required typed scalar parts, one flat 73-field Boolean record and one opaque string result. Supported response encodings include verified ISO-8859-1 under the existing encoding-agreement policy. No implicit JavaScript Date or floating-point conversion is introduced.

All 12 NOAA operations have owned-server qualification. The 2026-11-09 live gateway retest succeeded for ten operations. `GmlTimeSeries` and `GmlLatLonList` returned non-SOAP provider responses, including `Not connected : ` after input adjustments, and were correctly refused. See the [NOAA qualification](../noaa-ndfd-qualification.md#all-operation-live-retest-on-2026-11-09).

## Upgrade Notes

Read [1.1.x-to-1.2.0 migration](../migration.md#from-11x-to-120). Regenerate matched catalogs, clients, OpenAPI and gateways from original sources. Affected exported names and stream `recordType` references can change, and stream records now contain mapped DTO values instead of lexical attribute bags. Preserve adopted app/test scaffolds under existing skip/force rules.

Legacy streaming retains a UTF-8 parser; checked encoding agreement does not broaden it or the narrower direct runtime. Dates remain type-level and bigint gains no JSON convention. Stream memory depends on record size and transport/parser buffering; committed responses truncate on failure.

## Validation

Focused CLI, composition, streaming and NOAA regressions passed, and the locally packed candidate generated a typechecked two-source consumer with independently owned SOAP dispatch and mapped HTTP responses. Consumer docs, extracted skill and explicit npm contents were validated.

Final acceptance requires the matching successful conformance and complete release-preflight evidence recorded with the draft PR, including product CI, installed consumers, generated examples and skill ZIP/checksums. Publication remains separate; earlier recovered or partial evidence does not substitute for that gate.

## Notes

Target release: `v1.2.0`. This candidate task creates no tag and performs no publication.

One package distributes both legacy and checked profiles; native multi-service composition currently joins legacy-generated routers only. Checked composition and checked incremental decoding remain deferred. General SOAP encoding, encoded arrays/shared graphs, arbitrary RPC records, multiple return values and declared RPC faults remain outside the bounded RPC profile.

Private provider captures, credentials and generated proof projects remain outside the npm package. Package contents retain the generic implementation, declarations, consumer guides and required generation resources. A final versioned release preflight must validate the complete candidate before commit, tagging or publication; previous full-suite evidence plus focused test recovery is not an already completed v1.2.0 release preflight.
