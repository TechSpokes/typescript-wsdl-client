# TypeScript WSDL Client v1.1.1

## Correct array types from wrapping sequences

This patch preserves occurrence bounds declared on wrapping `xs:sequence` nodes when generating element types. See the [project overview](../../README.md) for the generation pipeline.

## What This Improves

A sequence with `maxOccurs="2"` around an address element now generates `address: AddressType[]` instead of a scalar address. Sequences with `minOccurs="0"` and repeated bounds generate optional arrays, including finite limits and `unbounded`.

The corrected catalog metadata flows into client types, OpenAPI schemas, and gateway responses. Consumer fixtures verify that both addresses survive the existing array-wrapper flattening behavior.

## Upgrade Notes

Update the package and regenerate your clients, OpenAPI specifications, and gateways from their WSDL sources. Review the generated diff: affected scalar properties become arrays, and properties inside optional sequences can become optional. Adapt consuming code to these corrected types.

Corrected array metadata can activate existing OpenAPI wrapper flattening, changing an affected REST object wrapper into an array. Review REST payload schemas and consumers when regenerating gateways; existing wrapper-flattening options retain their meanings.

This patch preserves the previous behavior across `xs:choice`, `xs:all`, zero-maximum sequence subtrees, disabled elements, and wildcards. It adds no finite-array-length or sequence-order runtime enforcement, CLI options, or catalog fields. See [supported patterns](../supported-patterns.md#fully-supported) for the compatibility boundary.
