# TypeScript WSDL Client v1.9.0

## More existing SOAP contracts through checked generation

Checked generation accepts more XSD scalar-content and union shapes, supports expanded QName values and carries source documentation into generated artifacts. For setup and profile selection, see the [root README](../../README.md).

## What This Improves

Move a supported WSDL to the checked pipeline without rewriting empty complex-content extensions that inherit simple content. The generated SOAP client and gateway validate the inherited datatype and preserve its text under `$value`. OpenAPI and TypeScript carry annotation text from the selected operation and its schema.

## Highlights

- Empty effective complex-content extensions inherit the exact scalar datatype.
- Lexical unions support more non-contextual atomic types and lists of atomic values.
- QName values carry their namespace URI and local name in generated JSON and TypeScript.
- Generated checked clients, routes and OpenAPI retain selected source annotations.

## Upgrade Notes

Regenerate the checked client, capsule, OpenAPI and gateway together. For a union without QName members, supply the full XML spelling as a string. For example, a list member uses `"1 02"`. Existing lists of atomic unions continue to use token arrays or their documented whole-list witnesses.

When migrating a lexical QName to checked generation, provide `{namespace, local}` using the URI from the original XML namespace binding. For a QName-bearing union, provide the lexical text and its namespace bindings in `{$value, $namespaces}`.

See the [support guide](../supported-patterns.md#checked-migration-from-legacy-generated-shapes) for selection, array wrappers and other checked migration differences.
