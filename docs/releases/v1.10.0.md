# TypeScript WSDL Client v1.10.0

## Standalone checked SOAP clients

Generate checked TypeScript SOAP clients for applications that connect directly to a SOAP service. See the [v1.10.0 README](https://github.com/TechSpokes/typescript-wsdl-client/blob/v1.10.0/README.md) for installation and profile selection.

## What This Improves

Generate from the original WSDL and its authorized imports. The standalone client uses the same source qualification and operation contracts as the checked pipeline, so requests, responses and declared faults follow the same validation rules when the client is deployed on its own.

## Highlights

- `wsdl-tsc client --model checked-components-v1` emits the checked client and its artifacts.
- `generateCheckedClient` exposes the equivalent typed package-root API.
- Operation capsules and portable WSDL/XSD snapshots travel with the generated client.

## Upgrade Notes

Legacy generation remains the default. To adopt standalone checked generation, keep `@techspokes/typescript-wsdl-client` as a runtime dependency and deploy the complete client output directory. Follow the [standalone checked client guide](https://github.com/TechSpokes/typescript-wsdl-client/blob/v1.10.0/docs/checked-generation.md#standalone-checked-client) for endpoint and snapshot configuration.

## Validation

- An isolated npm installation verifies standalone CLI and API parity with the checked pipeline's client.
- A relocated client completes a SOAP 1.1 success and a declared fault against an owned endpoint.
- Invalid values, mixed capsules and missing or altered snapshots refuse before SOAP dispatch.
- Release preflight validates the npm package, generated pipeline and agent skill artifact.
