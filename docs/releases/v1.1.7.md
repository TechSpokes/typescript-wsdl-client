# TypeScript WSDL Client v1.1.7

## One checked generation workflow with simpler project setup

This patch offers legacy generation and one opt-in checked component workflow for early testing and feedback. It carries forward the complete WSDL-to-gateway preview from the unpublished v1.1.6 candidate, reduces repeated preparation and separates generated source bookkeeping from optional user configuration.

## What This Improves

Choose `pipeline --model checked-components-v1` to generate a typed SOAP client, OpenAPI, Fastify gateway, runnable app and scaffold tests from a supported WSDL file or URL. An unambiguous service needs no authored selectors or graph records. Declared same-origin imports/includes and authorized redirects are acquired recursively; a reusable project decision permits each additional metadata origin. Planning reports preserve operation identities and explain missing dependencies, ambiguity and unsupported capabilities.

Generated hosts load their own copied source and capsule records and start without copying a configuration file. Optional endpoint, destination restrictions, host and trust overrides stay concise. Calls use the selected WSDL address or explicit override, and empty restrictions continue denying access. Runtime metadata stays offline, with physical sources and native artifact compatibility checked independently.

Explicit companion associations acknowledge their existing validation scope. Native mappings derive unique payload/record paths and fixed wrapper exclusions; ambiguous record paths remain user choices. The complete companion payload, declared faults and required schema metadata retain their checks. This is buffered scoped processing, without automatic companion discovery or full-response validity in a merged declaration universe.

Start with [Try Opt-in Checked Generation](../checked-generation.md) for the bundled trial and feedback path. The [checked gateway reference](../checked-gateway.md) describes advanced controls, regeneration and compatibility.

## Upgrade Notes

Use Node.js 24 or newer. Omitting `--model` preserves legacy generation. The unpublished `checked-direct-v1` generation choice and `checkedDirect` pipeline option are removed; migrate those experiments to `checked-components-v1` and regenerate the complete project. Existing v1.1.5-issued direct clients retain `checkedDirectRuntimeV1`, its protocol and explicit owned-loopback execution restrictions.

Regenerate matched clients, capsules, copied sources, gateways and host scaffolds deliberately. Generated source bookkeeping uses `checked-source-resources-v2`, separately from the component runtime protocol. Consumer-owned server/config/test files are preserved unless their force option is selected; review customizations before refreshing them. Complete older explicit source configurations remain supported as advanced inputs.

Refresh consumer lockfiles separately for transitive security patches. The narrow `checked-assessment-v1` API/report and exit codes retain their original scope; use component planning for component readiness. OpenAPI does not express every native scalar, ordering or wildcard rule. Missing required schema metadata and strict wildcard failures remain refusals, and the preview adds no validation bypass or XML response negotiation.
