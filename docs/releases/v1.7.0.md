# TypeScript WSDL Client v1.7.0

## Checked buffered SOAP credentials, headers and source fidelity

Checked clients and gateways now carry the remaining bounded buffered SOAP capabilities through native validation and the established transport. Legacy generation remains the default.

## What This Improves

Services requiring configured credentials, mutual TLS or declared literal headers can use the checked path while retaining schema, scalar, occurrence, fault and endpoint checks. Legal metadata names, supported cycles and explicit metadata encoding context survive generation and relocated runtime reconstruction without rewriting original evidence.

## Highlights

- Reuse Basic/Bearer, PEM/PFX, UsernameToken, outbound X509 signing and bounded NTLM builders.
- Validate declared literal headers and require implemented processing for targeted mandatory blocks.
- Preserve distinct declared header-fault outcomes after native Body and SOAP Fault validation.
- Support endpoint queries, bounded HTTP compression and observed HTTP/XML Base context.
- Retain original metadata bytes and charset context across portable source snapshots.
- Preserve the delivered response-encoding and envelope/header receiver behavior.

## Upgrade Notes

Update the checked runtime dependency and regenerate matched artifacts when adopting declared headers or metadata context. Existing runtime bindings remain in use; legacy defaults and frozen direct contracts retain their restrictions. Runtime credentials use the existing upstream configuration schema and environment references. Metadata credentials remain a separate sink.

Handle `soap-header-fault` when using declared header faults. Mandatory incoming headers require programmatic processors that implement their semantics; configuration or QName recognition alone cannot acknowledge them. Compressed `responseBytes` remain original wire evidence, while decoded XML has its own bounded processing.

See the [migration guide](../migration.md#from-165-to-170) and [buffered combination table](../checked-gateway.md#buffered-transport-and-runtime-credentials).

## Validation

Qualification covers independent byte, URI, token, signature and challenge-response expectations; owned HTTP/verified HTTPS; portable installed generated consumers; native rejection and cleanup controls. Standalone conformance, release preflight, package contents and skill artifacts are verified with Linux/Windows Node 24/26 hosted qualification on the final candidate.

## Notes

Streaming, general attachments, type-part/encoded headers, incoming cryptographic security and richer policy families retain their separate owners. Outbound signing does not authenticate incoming responses. No production SOAP provider is contacted, no default changes, and publication remains a maintainer action after draft and artifact verification.
