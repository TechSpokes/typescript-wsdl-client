# TypeScript WSDL Client v1.1.4

## Explicit SOAP imports in generated clients

This patch replaces generated SOAP namespace imports with named runtime imports and explicit type-only imports. See the [project overview](../../README.md) for the generation pipeline.

## What This Improves

Generated clients compile with strict NodeNext and verbatim module syntax while importing only the SOAP runtime function they use. Custom client names that match SOAP exports receive local aliases, so client generation stays valid for names such as `Client`, `IOptions`, `ISecurity`, and `createClientAsync`.

Buffered and streamed clients retain their existing behavior. Integration tests now have a dedicated typecheck, and both Node 24 and Node 26 CI exercise compiled generated clients.

## Highlights

- Generate a named `createClientAsync` import and type-only `Client`, `IOptions`, and `ISecurity` imports.
- Alias SOAP imports when a custom generated client name would collide with an imported identifier.
- Validate buffered and streamed clients against the actual SOAP declarations and Node runtime.
- Typecheck integration tests and run compiled-client coverage in Node 26 CI.

## Upgrade Notes

Update the package and regenerate clients to receive the new imports. No generated API or configuration migration is required.

Updates from v1.1.2 also include the dependency security maintenance prepared in v1.1.3. TypeScript remains on the maintained 6.x line, and Node 24 remains the minimum supported runtime.
