# Checked lexical atomic unions

## Selected implementation outcome

Extend opt-in checked component values to unions whose effective atomic members have XSD primitive string, decimal or boolean, without contextual/document-wide obligations. Decimal includes the existing integer-derived types. Every admitted union value uses one lexical JSON/TypeScript string; native source formation, member selection and value validation remain authoritative.

The [standalone implementation issue #490](https://github.com/TechSpokes/typescript-wsdl-client/issues/490) owns this bounded source/schema/value packet under #179/#183/#184/#187, with HTTP representation through #410 and paired evidence in #397/#207. Three fresh experts selected it after the accepted Escapia npm consumer upgrade and approved this brief with no blocking findings. Preparation does not implement the feature or dispatch another release.

## Why this gap

The legacy `xs-union-simple-type` registry row already promises named/inline unions, TypeScript union aliases and OpenAPI generation. Checked source correspondence and scalar projection independently refuse non-string union members, despite the native scalar owner already implementing ordered heterogeneous membership. This is a concrete replacement-parity gap with existing fixtures and owners.

#478 remains a distinct source-contract assessment, not a demonstrated regression in a supported gateway. Its content-mapper, scalar identity and correspondence duties are not solved by widening a gate. Streaming and incoming cryptographic security remain separate projects.

Preserve `test/conformance/fixtures/xsd/types/type-union-simple.wsdl` and its legacy row. That fixture lacks a complete executable binding/service; it establishes legacy catalog/shape expectations rather than installed checked SOAP execution. Add a separate complete bound fixture for the new capability.

## Fixed representation and membership contract

### Allowed members and source qualification

Admit only effective atomic members whose native primitive is string, decimal or boolean and whose obligations are empty. Reuse current formation and facet qualification: supported string/decimal restrictions, integer bounds and existing boolean enumeration/whiteSpace combinations. Do not expand unrelated facet languages.

Cover named members, inline members, aliases, nested unions and supported restrictions through the existing native flattening and identity owners. Whole-source construction/correspondence must precede operation selection and generation; unrelated invalid declarations cannot be hidden by choosing another operation. An unsupported member remains unsupported rather than being relabelled schema-invalid.

Exclude float/double, temporal/duration, binary, anyURI, QName/NOTATION, identity/DTD/document-wide obligations and dynamic types from new union admission. Preserve existing standalone encodings for those families. Unions containing list members and heterogeneous union list items remain excluded; existing lists of primitive-string unions retain their current representation and eligibility.

### Lexical strings and ordered assessment

Keep the complete parsed XML character or attribute value before member-specific datatype whitespace processing. Preserve signs, leading zeros, decimal scale and significant whitespace as a lexical string, without JavaScript numeric conversion. XML entity spelling, quote style and original XML byte formatting are not part of this lexical-value promise.

Use native XSD 1.0 declaration order: memberTypes order followed by inline members, with existing recursive flattening. On every fresh inverse, assess the same lexical string and choose the first successful effective member. Apply the successful member's normalization through the native owner; do not globally trim/collapse, coerce a JSON number/boolean or let a caller select another branch. Union-level facet failure after selection is terminal, not permission to retry a later member.

The internal selected member and typed value remain native evidence. Public request/success/fault values and generated TypeScript are lexical strings, including when the selected member is numeric or boolean. OpenAPI and runtime schemas describe strings with native supplemental validation; overlapping members must not become an exclusive oneOf assertion.

Use hand JSON such as `"+007"`, `"+01.00"`, `"1"` and `" 1 "` with independently specified membership outcomes. Include restricted string alternatives in negative cases; an unrestricted string member legitimately accepts many otherwise invalid numeric words.

### Typed fixed/default semantics

Carry enough transient authenticated constraint evidence to compare native typed values, not canonical text alone. A string enumeration member accepting `"1"` followed by decimal assigns fixed `"1"` to the string family, while `"+1"` selects decimal; their equal canonical text must not make the fixed check pass. A decimal-family fixed value and a differently spelled equal decimal/integer value must retain native equality.

Reuse `datatypeValues.sameValue` or the existing native scalar equivalence owner, with its source identity, resource accounting and primitive-family rules. Do not implement a new equality algorithm. Preserve original default/fixed lexical evidence, default augmentation, inherited attribute constraints and existing nil-with-fixed rules.

Qualify fixed/default behavior in element, attribute and existing simple-content slots, including a boolean/string family-collision control. Union-level enumeration and member restrictions must use native typed semantics too. Keep new constraint data private/transient; source capsules reconstruct native mappings and do not require a new serialized constraint representation. Preserve public type-only and older runtime compatibility.

Retain default source lexical witnesses: rewriting `"+1"` to canonical `"1"` can change the selected member. An absent optional element stays absent; present empty elements and missing constrained attributes follow their existing source-default/fixed rules. Preserve fixed-element nil refusal and attribute validation on nil complex values.
