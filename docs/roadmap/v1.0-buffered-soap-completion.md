## Scope exclusions and continuing ownership

The existing custom profile requires consumer implementation; configuration establishes no generic security protocol. Incoming mandatory literal headers require a processor for the exact pinned declaration after native validation. QName recognition does not establish understanding, and outbound signing does not authenticate incoming responses.

Streaming, attachments, type-part/encoded headers, incoming cryptographic verification/encryption/replay, richer policy and broader bindings retain their existing owners. Native source/schema/value gaps and semantic retirement remain separate obligations. No production-provider transaction or default change was part of this completion.

The next selected task is ordinary [published-package consumer acceptance](v1.0-published-consumer-acceptance.md), followed by selection of a concrete source/schema/value capability from #397/#207. Reuse completed evidence rather than rerunning v1.7.0 CI, conformance, packaging or release preflight for record reconciliation.
