## Verification decisions

The active `main` ruleset observed at the v1.10.0 head covered deletion and non-fast-forward changes. The branch had no classic branch protection. The repository's final-head and merged-commit verification requirements still govern release operations. Live ruleset and CodeQL policy belong to the maintainer. [Active ruleset](https://github.com/TechSpokes/typescript-wsdl-client/rules/7673730)

| Check | Bound inputs and evidence | Decision |
| --- | --- | --- |
| Local focused tests and independent review | Staged and working-tree content, scoped commands, candidate examples and fixtures | Retain evidence on the reviewed diff and recheck affected work after changes. |
| Full delivery on Linux Node 24 | Checkout tree, lockfile, commands, runner image, Node/npm, install and network conditions | Require the current PR run and the merged-commit run. |
| Audited reference | Pinned engine and fixtures, command, revision/tree and dirty state, probe logs | Keep per-run reference qualification and provenance on all existing cells. |
| Installed Linux Node 26 and Windows Node 24/26 | Actual OS/architecture and runtime, fresh isolated installs, generated artifacts and permissions | Keep each platform result tied to its run. |
| Full manual matrix | Complete installed discovery per compatibility cell | Use dispatch for broader platform or verification qualification. |
| Release preflight | Exact staged candidate and working tree, live root/app pins, lockfile, examples, CI and local skill ZIP | Run complete preflight once per final uncommitted tree. |
| Package contents and smokes | Byte identity of the candidate archive, package navigation, fresh consumer and transport conditions | Reuse one candidate tarball within a delivery run. Repeat qualification for new package bytes. |
| CodeQL | GitHub analysis event, ref and commit, workflow and scanner state | Keep separate PR and main analyses. |
| Draft skill delivery | Peeled reachable tag, marker and draft state, uploaded ZIP digest, attestation identity and consumer exercise | Verify the tag-triggered artifact and compare the uploaded bytes. |
| npm publication | Published release eligibility, peeled tag, trusted workflow identity, package and provenance | Retain current publisher until the exact archive handoff is qualified for that identity. |

The release PR's package and lockfile versions, packaged README and checked-generation guide differ from the earlier feature tree. Even a version-only edit can change the archive and npm cache key. The tag-triggered draft verifies the actual uploaded ZIP, while local preflight verifies its own generated ZIP. They establish different claims. [Draft example](https://github.com/TechSpokes/typescript-wsdl-client/actions/runs/44507113401)

The package workflow's targeted `release:publish-check` step took 18s. Its publish step took 19s, including the separate `prepublishOnly` lifecycle build. The green build checks the tag source and package layout. It supplies no digest binding for what the second job uploads. [Publication example](https://github.com/TechSpokes/typescript-wsdl-client/actions/runs/44521741102)

### Matching and invalidation

The two historical PR/main pairs matched at the source-tree level. The prior feature PR and its main run used Node 24.22.2 and npm 11.19.1 but ran on different Ubuntu image revisions. There were no producer artifacts binding reports, package bytes or reference provenance to the destination commit. GitHub's statuses and release gates apply to their own run and checkout.

| Case | Evidence disposition and fallback |
| --- | --- |
| Identical PR and destination trees | Record the match and require the destination run. |
| Changed base changes the checked contents | Require a new PR result for the new checkout and compare the merged tree against preflight. |
| Different toolchain, runner or install inputs | Use the check from the correct environment. |
| Missing, expired, failed or cancelled result | Rerun the affected check and require success. |
| Wrong repository, workflow, attempt or trust context | Discard the result for the gate. |
| New archive bytes, tag identity or marker state | Validate the relevant bytes and release state again. |

### Rehearsing the npm tarball handoff

The [qualification workflow](../../.github/workflows/release-tarball-qualification.yml) validates the file list and contents inside the actual npm archive after checking npm's integrity report. It passes the successful build's immutable Actions artifact ID and SHA-256 to a separate verifier. The verifier independently establishes the checkout and run identity and checks the downloaded artifact's manifest and digest. The trial runs with read-only permissions and uses the candidate checkout and manifest version in place of a published release.

Before switching the publisher, the production build and receiving job must enforce current `release-state` checks on the peeled final-form tag and published GitHub Release. The receiving job must resolve the tag independently and use the archive from the successful build in the same run and attempt. The trusted publisher remains `release-package.yml` in the same repository. npm 12 accepts an explicit tarball. The maintainer-triggered publish run must establish that npm accepted the existing GitHub OIDC identity and that the npm provenance subject and registry `dist.integrity` refer to the validated archive. [npm publish](https://docs.npmjs.com/cli/v12/commands/npm-publish/) · [Trusted publishing](https://docs.npmjs.com/trusted-publishers/)

## Measurements within fresh runs

### Checked gateway harness

On the v1.10.0 tree, the hosted Linux Node 24.22.2 and npm 11.19.1 delivery used 229.74s for installed checked gateways, including 79.29s for the primary owned HTTP/SOAP probe and 55.64s in 17 consumer builds. The npm cache missed. The behavior-identical timing probe on local Ubuntu WSL with the same Node and npm versions spent 21.85s in the primary wire phase. Eight listener starts accounted for about 14s, the cancellation closed upstream in 90ms, and the configured timeout retained its full second. Full local delivery took 14m 53s and the checked gateway case took 299.24s. Local wall time includes other host workloads. [Hosted baseline](https://github.com/TechSpokes/typescript-wsdl-client/actions/runs/44505666727/job/135496486437)

The primary exchange, configuration-field refusal, and source/artifact controls still exercise the installed process entry. Five policy variations, including the explicit timeout, now call the installed `buildServer` and open fresh real listeners in the isolated probe process. A repeat Linux run attributed 69.06s to graceful shutdown after the cancellation case. The primary probe now uses short-lived HTTP connections so it releases its own sockets before shutdown. The consumer compile checks, separate SOAP 1.1 and 1.2 controls, cancellation, production-only and relocation assertions remain in full delivery and installed qualification.

On Windows Node 24.21.0, the primary wire phase took 20.83s in the v1.10.0 delivery baseline and 11.65s in the intermediate listener-reuse version with the pooled HTTP client. Both reported 40 HTTP calls, 28 refusals and 26 upstream requests. The measured configured timeout was 1.07s in the second probe, and the cancellation closed the upstream connection in 56ms. The two timings used the existing local npm cache under different delivery workloads.

Three executions of the final probe against one fresh Ubuntu Node 24.22.2 consumer took 8.41s, 8.15s and 7.98s. The first spawned gateway stopped in 25–37ms. The configured timeout still took 1.04–1.06s, and cancelling the in-flight HTTP call closed the upstream connection in 47–60ms. A separate failure control after an in-process listener opened observed closure of that listener and the upstream server, followed by removal of the consumer directory.

### Routine platform selection

The current `test:platform` selection includes every unit and tooling file plus targeted HTTP/SOAP, application, process and file ownership integrations. Linux Node 24 full delivery owns broad product discovery. The compatibility matrix also exercises installed legacy and relocated checked consumers over TLS, platform-specific file and process controls, and the audited independent reference suite. Full manual dispatch adds the remaining installed matrix.

The narrower experiment removes only `casing`, `catalog-meta`, `primitives`, `tools` and `wildcard-algebra`. These exercise in-memory identifier and metadata transformations, primitive mapping and algebra under Linux Node 24 delivery. The experiment retains tests that read files, launch processes, use TLS or permissions, or exercise independent source or wire evidence. The release retains the current platform selection and full manual matrix until a narrower selection is qualified with repeatable savings.

Both selections ran on archived v1.10.0 with installed locked dependencies. The old selector discovered 200 files and 3,529 cases on every cell. An explicit allowlist discovered 195 files and 3,396 cases. The platform timing includes concurrent local workloads and the Linux cell uses Ubuntu WSL.

### Dependency freshness

On local Windows Node 24.21.0 with npm 11.19.0, the unchanged v1.10.0 manifest and retained cache returned all 19 identical ranges. Serial `npm view` took 52.20s and 52.87s. Four-at-a-time batches took 11.66s and 13.91s. npm view still consults the configured registry and uses Node's system trust. The versioned diagnostic preflight took 16.32s total, including 10.05s for the lookup phase, with delivery, examples and skill packaging skipped by flags.

The maintenance command kept the root and generated app ranges and accepted the lockfile. A failing command and malformed npm output each failed before example generation, full CI and skill packaging. Tracked-content checks passed on those probes. The focused lookup tests cover TypeScript's maintained major, a manifest pin newer than npm's answer, input order and the four-process limit.

On the same v1.11.0 metadata in a disposable Windows Node 24.21.0 checkout, a serial diagnostic preflight took 48.24s with 39.43s in freshness. The concurrent command took 20.92s with 15.68s in freshness. Both used npm 11.19.0, a retained cache and the same diagnostic flags. Scoped lockfile and generated-app pin drift controls failed before CI and skill packaging. On Ubuntu Node 24.22.2 and npm 11.19.1, the live lookup matched all 19 pins in 16.36s with a new cache. The malformed-response probe likewise failed before CI or packaging there.
