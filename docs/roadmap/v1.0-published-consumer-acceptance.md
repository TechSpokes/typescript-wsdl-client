## Implementation contract

### Exact published artifact and isolation

Install the generator by exact npm version `1.7.0` in an isolated consumer tooling project. Record registry tarball URL, SHA-512 integrity, available authenticated provenance, lockfile identity, npm/Node/platform and resolved public package paths. Use supported npm verification rather than treating a bare attestation URL as proof.

The consumer must use the registry artifact, not `npm pack`, a local tarball, workspace link, private package import or checkout fallback. Restrict generation and execution filesystem access to the isolated consumer where supported, and prove a read of a known checkout-only sentinel is denied. Keep acquisition/install configuration separate from the subsequent no-checkout execution proof.

Verify current supported Node/npm instructions first. Preserve both the emitted dependency declaration and the resolved app runtime identity. If a future compatible version causes `^1.7.0` to resolve differently, record that observation and stop the exact-1.7.0 assertion; do not rewrite the manifest or force a candidate tarball to manufacture a pass.

### Public authoring and ordinary app installation

Use the installed public `wsdl-tsc pipeline` CLI with `--model checked-components-v1`, explicit source/config/output paths and `--init-app`. Generate client, OpenAPI, gateway, app and scaffold tests into explicit `.generated/` consumer paths. Pin the complete source inventory rather than silently selecting around a rejected declaration.

Exercise one documented package-root API, such as `planCheckedComponents` or `runGenerationPipeline`, in a separate output directory or read-only planning call. The public API must agree with the selected CLI operation and source identity; no `dist/compiler` or other private import is allowed.

Run the generated app's normal installation command without an explicit runtime package argument, then its emitted `typecheck`, `test` and `build` scripts. Verify the app has its own resolved runtime dependency and that its lockfile integrity matches the observed registry artifact. Run from the app directory without repository-only paths or repository development dependencies; the emitted app's own devDependencies remain available for its scripts.

Start the built app using its documented start/config path, select an owned ephemeral endpoint, and verify health and OpenAPI before business requests. Keep generated scaffold tests distinct from the independent SOAP/HTTP oracle.

### Owned execution and regeneration

Author independent expected XML/namespaces and JSON for one valid request, normal response and declared fault. Verify the captured request's binding/action/content type, selected values, success status/body and complete declared fault envelope. Expectations must not come from production serialization or generated mocks.

Reject invalid HTTP input before any upstream request. Send one invalid upstream scalar/order mutation and assert failure with no successful value. Use an explicit denied endpoint once and assert zero dispatch; these are selected boundary controls, not a rerun of the buffered security matrix.

Regenerate once without force options after a benign consumer-owned app/config/test edit. Verify those edits survive and generated artifacts remain matched. Rebuild or recheck only what regeneration changes. Await the owned server and app processes, sockets and children on both success and failure.
